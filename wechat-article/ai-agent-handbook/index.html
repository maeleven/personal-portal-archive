阿里云开源的 AI Agent Handbook。是一本围绕企业级 AI Agent 开发与落地的技术手册，涵盖架构设计、Agent 构建、运行时、工具调用、多 Agent 协作、安全治理、性能调优以及企业实践等内容。

全书共 30 章，提供中英文版本，完全免费，采用开源方式持续维护。

GitHub：https://github.com/aliyun/ai-agent-handbook

如果你对 AI 编程感兴趣，或者已经开始尝试使用大模型开发自己的 AI 应用，这本书值得花点时间了解一下。

一、为什么值得读这本书？

这两年，AI 编程发展得非常快。

从 ChatGPT 辅助写代码，到 Cursor、Claude Code 等 AI 编程工具，再到基于大模型开发 Agent，软件开发的方式正在发生变化。

尤其是 Agent。

以前，我们使用大模型，主要是向它提问，让它生成代码或者回答问题。

现在，我们希望 AI 能够真正完成任务。

例如：

• 让 AI 自动分析代码、定位 Bug、修改代码并运行测试。
• 让 AI 搜索资料、分析信息，自动生成研究报告。
• 让 AI 调用数据库、浏览器和业务系统，完成复杂的工作。
• 让多个 Agent 分工协作，自动完成一项复杂任务。

这些应用看起来并不复杂，真正开发起来却会遇到不少问题。

如何管理 Agent 的上下文？如何保存任务状态？如何让 Agent 在执行失败后恢复？如何管理工具调用权限？如何追踪执行过程？如何判断任务是否真正完成？

这些问题已经超出了简单调用大模型 API 的范畴。

让 Agent 跑起来并不难，难的是让它稳定、可靠、可控地完成任务。

这正是 AI Agent Handbook 想要解决的问题。

它的前身是阿里云 2025 年发布的《AI 原生应用架构白皮书》。这次经过重新梳理，以开源项目的方式持续维护，希望把企业在 Agent 落地过程中的经验、问题和解决方案沉淀下来。

它不是一个 Agent 开发框架，也不是可以直接运行的 Demo 项目，而是一套面向工程实践的技术知识体系。

二、30 章内容，覆盖 Agent 开发的完整生命周期

这本书最大的特点，是没有只关注 Agent 的开发过程，而是按照一个 Agent 从设计、构建到上线运行、持续优化的完整生命周期组织内容。

全书分为六大篇章，另外还有前言、调研报告和总结展望。

▍ 1. 架构篇：先搞清楚 Agent 应该怎么设计

第 01–02 章
• AI 原生应用的新阶段
• Agentic Application 参考架构

这一部分主要讲 Agent 的应用形态、架构设计和技术选型。

并不是所有问题都适合用 Agent 解决。

有些场景使用传统程序和规则引擎就够了，有些适合使用工作流，有些才真正需要 Agent 的自主规划和执行能力。

如何判断应用形态？如何设计 Agent 系统的整体架构？这是开发之前首先要考虑的问题。

▍ 2. 构建篇：Agent 到底是怎么开发出来的？

第 03–06 章
• 范式：Harness 的主流构建方式和责任边界
• 任务：编排、长程推进与协作流转
• 信息：上下文、状态与可复用能力资产
• 行动：受控执行、验证反馈与交付准备

这是我认为开发者最值得重点阅读的部分。

这里有一个重要概念：Harness。

简单理解，模型负责提供智能能力，Harness 则负责组织模型完成任务。

它需要管理上下文、工具、任务状态、执行环境和反馈机制，让模型能够按照一定的规则持续推进任务。

例如，一个 Coding Agent 不只是让模型生成代码，还需要读取项目文件、分析代码结构、修改文件、执行命令、运行测试，并根据执行结果决定下一步行动。

这些过程都需要 Harness 来组织和管理。

这也是为什么现在开发 Agent，不能只研究 Prompt 和模型 API，还需要理解整个 Agent 执行系统的设计。

▍ 3. 运行篇：如何让 Agent 稳定运行？

第 07–12 章
• Agent 运行时与沙箱
• Agent 状态存储与语义资产
• AI 网关与统一流量治理
• Agent 异步任务与自动化流程
• Multi-Agent 协作与编排
• Agent 分布式通信

Agent 一旦开始执行复杂任务，就会遇到很多传统软件系统同样需要解决的问题。

例如，长时间任务如何运行？进程异常退出后如何恢复？如何隔离不同 Agent 的执行环境？多个 Agent 如何协作？如何管理模型调用流量？

这些问题涉及运行时、沙箱、状态存储、任务调度和分布式通信。

如果你希望开发能够真正投入使用的 Agent 应用，这部分很有参考价值。

▍ 4. 治理篇：如何保证 Agent 安全、可控？

第 13–16 章
• Agent 的可观测性
• Agent 安全
• AI 资产的发现与管理
• Agent 行为生成与质量验证

Agent 拥有一定的自主执行能力，也意味着它可能产生不可预期的行为。

例如，错误调用工具、访问未经授权的数据、执行危险操作，或者在没有完成任务的情况下给出成功结果。

因此，企业级 Agent 必须考虑权限控制、安全审计、运行监控和质量验证。

这部分重点讨论如何让 Agent 的执行过程可见、行为有边界、结果可验证。

▍ 5. 调优篇：如何持续提高 Agent 的效果？

第 17–24 章
• 模型调优
• Agent 调优总览和实践
• Agent 轨迹数据
• Agent 运行时数据处理
• Agent 黄金数据集
• Agent 优化：Badcase
• 受控自进化
• Agent 边缘运行时与全球优化

传统软件的测试通常关注输入和输出是否符合预期。

Agent 则更加复杂。同样的任务，可能会经过不同的推理过程，调用不同的工具，最终产生不同的结果。

因此，需要记录和分析 Agent 的执行轨迹（Trajectory），结合 Trace、黄金数据集和 Badcase 分析，建立持续评估与优化的机制。

这部分涉及不少值得深入研究的新技术和工程方法。

▍ 6. 实践篇：企业里究竟如何使用 Agent？

第 25–29 章及专题

前面几篇主要讲方法和技术，这一部分则更关注真实应用。

包括：

• 研发效能：代码审查、补丁交付、研发流程自动化。
• 设计工程：AI 在设计工作流中的应用。
• 运维、安全与企业 IT：智能运维、故障分析和自动化处理。
• 客户、销售与运营：客户洞察、业务运营和流程自动化。
• Agent Infra：多 Agent 协作等前沿实践。

另外还有 Jev 结构化决策、Personal Agent 和 FDE 工程实践等专题。

这部分值得关注，因为它能帮助开发者了解 Agent 不只是一个聊天机器人，还可以进入研发、运维、运营等实际业务流程。

▍ 7. 总结与展望：从 Agent 应用走向 Agentic OS

第 30 章

最后讨论 Agentic Application 向 Agentic OS 演进的趋势。

随着 Agent 数量和应用规模不断增加，越来越多的基础能力可能从单个应用中抽离出来，成为统一的系统级基础设施。

这也是 Agent 技术未来值得关注的方向。

三、这本书有哪些值得重点关注的技术？

如果你是程序员，我建议不要只把它当成一本 AI 入门资料，而是重点关注几个工程技术方向。

1. Harness：Agent 的执行框架

这是 Agent 工程化开发中非常值得研究的方向。

模型本身并不负责所有事情，任务管理、上下文管理、工具调用、执行控制和结果验证，都需要外围系统配合。

理解 Harness，有助于从简单的模型调用转向完整的 Agent 系统开发。

2. Agent Runtime：Agent 的运行时环境

Agent 需要一个能够执行任务的环境。

特别是 Coding Agent，可能需要访问文件系统、执行 Shell 命令、安装依赖、运行测试，甚至启动其他程序。

如何通过沙箱实现环境隔离？如何管理资源和执行权限？如何支持长时间运行的任务？这些都是很实际的工程问题。

3. Multi-Agent：多个 Agent 如何协作

一个 Agent 能力有限时，可以将复杂任务拆分给多个 Agent。

但多 Agent 并不是简单地多启动几个模型实例，还涉及任务分配、消息传递、状态同步、协作编排和失败处理。

如何设计可靠的多 Agent 系统，是一个值得深入研究的课题。

4. Agent 可观测性与评估

Agent 的执行过程具有一定的不确定性，不能只看最终输出。

需要知道它做了什么、调用了哪些工具、为什么失败、消耗了多少 Token，以及最终任务是否真正完成。

Trace、Trajectory、黄金数据集和自动化评估，是建立 Agent 质量体系的重要基础。

这些技术方向也与传统软件工程中的分布式系统、任务调度、可观测性和测试体系有不少联系。
