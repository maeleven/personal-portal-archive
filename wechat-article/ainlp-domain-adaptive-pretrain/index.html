领域自适应之继续预训练 demo

前言

大家平常基本上都是基于预训练模型比如bert热启，然后fintune自己的下游任务。如果大家手头上还有足够多的领域内数据，请继续先在其上二次pretrain一把，然后基于该模型热启去fintune，不出意外的话是可以拿到一点收益的，上述所说的pretrain其实就是让预训练模型更好的适应当前的数据集。

那我们怎么pretrain呢？这就看当前的数据集特点了，如果能够设计一些细粒度的预训练任务那是最好的，如果不能，那也没关系，我们可以只仿照原始bert的mlm任务就可以了，总的来说就是：mlm保底的前提下，尽可能的设计一些细粒度的预训练任务。

本篇就写一个能够快速落地的预训练demo，供大家在自己的数据集上面试一试，注意：很多开源的预训练模型代码都有预训练的demo，如果是使用的特定的预训练模型可以看它的demo，但是很多其实是没开源预训练demo（核心），只给了一些fintune，相当于只给了你API，不给你核心技术。目前大家使用最多的应该是pytorch的transformers这个包了，我们就以此给demo。

简版

这里的demo，其实是通过官方demo精简出来的，特点就是简单快捷，主要说一下实际做的时候可能遇到的坑。
(1) 大家在使用的时候不知道有没有注意到，其实经常会使用transformers、pytorch-transformers或者pytorch-pretrained-bert，比如：
from transformers import BertConfig, BertForMaskedLM, DataCollatorForLanguageModeling或者from pytorch_pretrained_bert.modeling import WEIGHTS_NAME,CONFIG_NAME,BertPreTrainedModel,BertModel
那么它们是什么关系呢？其实它们不是独立开发的包，是一个体系下的，其中早期是叫做pytorch-transformers或者pytorch-pretrained-bert，transformers是最新的版本，其做了更多的修改和兼容，所以transformers有很多新的API，其实一些预训练模型在这些包中都是可以通用加载的。
(2) 我们知道transformers在加载的时候基本上使用的是from_pretrained，那么如果我们想直接加载比如'roberta-base', 那它就会先下载，但是有时候我们会去先下载好一些预训练模型比如：chinese_roberta_wwm_ext_pytorch，那我们直接给from_pretrained传本地路径也是可以的，但是这个时候就会遇到第一个坑：transformers一般使用from_pretrained加载的config形式是config.json，而chinese_roberta_wwm_ext_pytorch里面的命名是bert_config.json(pytorch_pretrained_bert中加载的)，所以我们要改一下名字即将bert_config.json改为config.json，当然了如果是在别的预训练模型上面热启，而且下载的模型里面正好是config.json就不用改了。
(3) 在使用下面demo进行预训练完后，保存模型的目录中是没有vocab.txt的，所以如果直接用其热启进行fintune，会报错：
AttributeError: 'NoneType' object has no attribute 'tokenize'
因为tokenizer的加载是需要vocab.txt的，所以我们可以将原始下载的预训练模型目录中的vocab.txt copy一份过来即可，比如chinese_roberta_wwm_ext_pytorch目录下的vocab.txt 。
好了给一下简单的demo吧：
import torchfrom transformers import BertConfig, BertForMaskedLM, DataCollatorForLanguageModelingfrom transformers import  BertTokenizer, LineByLineTextDataset, TrainingArguments, Trainer

bert_file = "./chinese_roberta_wwm_ext_pytorch"
config = BertConfig.from_pretrained(bert_file)tokenizer = BertTokenizer.from_pretrained(bert_file)model = BertForMaskedLM.from_pretrained(bert_file)print('No of parameters: ', model.num_parameters())
dataset = LineByLineTextDataset(tokenizer=tokenizer, file_path='./text.txt', block_size=512)data_collator = DataCollatorForLanguageModeling(    tokenizer=tokenizer, mlm=True, mlm_probability=0.15)print('No. of lines: ', len(dataset))
training_args = TrainingArguments(    output_dir='./outputs/',    overwrite_output_dir=True,    num_train_epochs=100,    per_device_train_batch_size=16,    save_steps=5000,)trainer = Trainer(    model=model,    args=training_args,    data_collator=data_collator,    train_dataset=dataset,)trainer.train()trainer.save_model('./outputs/')
说明：
(1) text.txt就是当前的语料，一行一个样本。
(2) 我们的mask token其实使用了DataCollatorForLanguageModeling这个API，如果有特殊的策略可以重写这个函数。
复杂版

这里所说的复杂版其实是基于这样一种场景：假设你有一些特殊的mask 策略，比如mask 实体等，想实现一个知识增强的mlm的预训练任务，甚至还想加一些我们前言所说的细粒度的预训练任务一起训练，那么上述的代码应该就满足不了你的需求了，那我们怎么办呢？
当然了，还是那句话，如果用的是一些特定的预训练模型，其开源了相应的预训练代码，那就直接用，这里所说的情况是我们没有用特殊的，就是很常规的想使用transformers来实现怎么做呢？
